## 3. Known model insufficiencies — deliberately not hidden

**Critical source-model counterexample M15:** `apply_synthetic_effect` accepts a structurally constructed Python `Reservation` object. There is **no cryptographic A0 signature verification** or independent A0 ledger proof at D. This is not a vulnerability discovered in a deployed system; it demonstrates why the source-only model is *not* production security logic. A later separately authorized implementation must reject forged/nonlive reservation tokens before effect time and independently witness that rejection.

**Critical observability counterexample M10:** D intentionally does **not** deduplicate repeat dispatches. Calling the effect function twice with the same valid-looking token increments the synthetic counter twice. This makes duplicate forwarding measurable and **must score BLOCK**, but it does not prevent the second effect. Exactly-once enforcement remains UNPROVEN.

**No physical independence:** A0, D, Q/F/E, H/G1/G2, C, J, worker, admin keys, backup systems and high-watermark services are not instantiated. The entire model can be held in one process and copied/rolled back. A copied data structure is not an independent witness.

**No concurrency proof:** Each function models an indivisible transition *by assumption*. The future test executor must challenge real DB transactions, simultaneous processes, lost ACK, and restart/restore. Source code with sequential calls does not demonstrate deployed linearizability.

**No full stop claim:** `stop_status` always returns `combined_stop_qualified=False` because no worker-tree liveness/termination measurement exists. D-first STOP may coexist with A0 admissions until A0 STOP is committed; A0-first STOP may coexist with outstanding D effects until D fences. No unsynchronized wall-clock inference is allowed.

**No apparatus correctness:** No VM, Linux cgroup-v2, route isolation, allowed/denied network positive control, file sentinel, quota, filesystem object, signature backend, key, clock, production API or persistence. M14 (whole-domain rollback) and M17 (late packet transport) are *specification-only* because a pure memory model cannot prove those properties.
