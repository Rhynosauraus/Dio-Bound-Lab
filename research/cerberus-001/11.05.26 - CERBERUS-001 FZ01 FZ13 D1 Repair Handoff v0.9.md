## 2. Narrow source differences

**FZ01 incoming damaged intent:** v0.7's exact-class `ReadIntent` check was followed by five direct field accesses. The new source uses an internal `_safe_field` for all five fields. A missing instance field becomes a sentinel and, on a structurally healthy journal, follows the existing `D_PRIVATE_READ_ATTEMPT_LOGGED_INVALID` in-memory append path. This still **cannot assert durable custody**, and the return flags remain no historical lookup, no receipt release and no new effect.

**FZ13 damaged historical journal:** v0.7's `_valid_prior_attempt` and `_valid_journal` directly dereferenced expected attributes, allowing missing fields to raise. The candidate validates every required field through `_safe_field`. It inspects exact-class instance `__dict__` membership, **not bare `getattr` defaults**, because the `DPrivateReadJournal` dataclass defines class-level defaults for `attempts` and `read_sequence`; deleting an instance field must not let those defaults silently reconstruct apparently valid evidence. A damaged journal returns `D_READ_JOURNAL_UNPROVEN`, `recorded_in_model=False`, `custody_gap=True` and all release/effect/lookup flags `False`. The invalid original journal is preserved as supplied, rather than reset.

**Scope and safety:** Only the additive candidate source is modified; the frozen v0.7 and v0.8 contents are unchanged. No new endpoint, signer, key, database, resource controller, external network, or runtime authority is created.
