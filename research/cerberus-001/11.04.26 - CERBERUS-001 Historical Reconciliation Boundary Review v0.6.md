## 1. Source-grounded v0.3 ↔ v0.4 ordering defect

The historical v0.3 `record_one_use_effect()` source calls
`commit_evidence.committed(reservation_id, sequence, digest)` and *denies
with `A0_COMMITMENT_UNPROVEN` if false* before performing its
`by_reservation` historical-effect lookup.

The v0.4 `OneShotCommitEvidence.committed()` adapter sets `_used=True` on
first attempt and returns `False` on every subsequent call to that **same
instance**, even if it would have been an exact retry. Taken together,
the most straightforward integration (reusing that adapter across a
successful first admission and a subsequent historical replay) can no longer
return the v0.3 `ALREADY_COMMITTED_HISTORICAL_ONLY` result documented in
EC02, nor the fenced historical result documented in EC03/EC04.

**Disposition of that unmodified integration: BLOCK (source-semantic).**
This conclusion follows from static control flow; it is **not** a measured
test failure. One could supply a new A0 challenge and new adapter for each
retry, but that changes the protocol and does not itself solve freshness,
authorization, revoked issuance keys, or globally durable nonce consumption.
Merely bypassing A0 to create a new effect would be an unacceptable fix.

## 2. New v0.6 source proposal — strictly D-internal classification

New **`11.04.26 - CERBERUS-001 D Historical Reconciliation Classifier v0.6.py`**
proposes an entirely separate read-only classifier over a D-owned snapshot
of already committed effects and D-side run/grant/generation fences.

- Exact original reservation ID, token-byte SHA-256, root/run/episode/action/
  grant/generation and D committed-event record must match.
- Duplicate reservation IDs or duplicate root/run/episode/action keys in the
  model snapshot fail closed. Invalid data types, bool-as-generation, and
  malformed sequences also fail closed.
- An existing effect can be classified as
  `D_PRIVATE_HISTORICAL_CANDIDATE` or
  `D_PRIVATE_HISTORICAL_CANDIDATE_AFTER_FENCE`, but every returned
  decision contains `release_to_external_caller=False` and
  `authorize_new_effect=False`.
- This source interface **does not accept or consume an A0 challenge,
  verifier, or commitment proof**. It makes no new admission and cannot
  count any additional effect.
- It also **does not record attempts**. A future D ingress interface must
  write all attempts, including failed and historical requests, and an
  independent witness must account for inbound attempts D did not receive.

This is a **candidate helper only**. It is not integrated with v0.3 effect
admission, its legacy raw interfaces remain present, and it is not a
complete historical receipt release implementation. The inputs are Python
dataclasses, not durable or cryptographically privileged D custody.

## 3. Proposed separation of future authenticated interfaces

`D.admit_new_effect()`: authenticate original A0 reservation envelope,
use freshly D-issued and atomically consumed A0 commit-proof challenge,
check independently fresh authority and D fences, recheck both uniqueness
constraints, and commit attempt/effect/fences through one durable writer.
Do not reuse a consumed A0 challenge across effects.

`D.reconcile_historical()`: log ingress/attempt independently of replay
deduplication; authenticate the principal and its historical receipt-read
rights; reverify the **original token** with separately enrolled historical
issuer key/snapshot (or comparably strong retained original auth evidence);
compare exact original byte digest and every recorded binding to immutable
D history; fetch only the existing receipt; never re-authorize effects.
If a D fence has since occurred, label historical only without treating it
as renewed admission. Release externally only under a separate privileged
receipt-disclosure policy. No code here implements that policy.

**Crash/revocation constraints:** D record and attempt/fence ordering
must be durable. An A0/D snapshot rollback, compromised original key,
unauthenticated caller, changed original signing-key registry, deleted history
or ambiguous proof cannot be papered over by this classification. Fences
operate on new effects; external historical disclosure policy is distinct
and requires explicit approval. An empty D history result **cannot authorize
a new effect**, and all new admissions must recheck D uniqueness inside
the actual effect transaction to avoid concurrent-writer races.
