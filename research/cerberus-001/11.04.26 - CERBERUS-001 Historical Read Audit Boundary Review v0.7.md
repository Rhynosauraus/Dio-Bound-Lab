## 1. Bounded defect: v0.6 has no attempt-custody stage

v0.6 \`classify_d_private_history(view, query)\` classifies matches in an already committed D effects view without A0 proof and rightly returns \`release_to_external_caller=False\` and \`authorize_new_effect=False\`. If an eventual D receipt-reconciliation endpoint simply calls that classifier on incoming requests, it could provide historical classification without leaving the distinct, durable read-attempt evidence needed to reconcile denied requests, duplicate retries, or externally witnessed requests absent from D. A pure classifier returning a result cannot satisfy the attempt-ledger requirement by itself.

**Disposition:** **BLOCK** against an integration that asserts complete attempt accounting based solely on v0.6. This is a source-semantic omission, **not** a demonstrated executed attack.

## 2. Smallest candidate: D-private first-stage read attempt journal

New \`11.04.26 - CERBERUS-001 D Historical Read Attempt Journal v0.7.py\` defines a pure append-only **in-memory** D-private read-attempt transition, separate from v0.6 historical classification and v0.3 new-effect admission.

- Every well-formed or malformed request presented alongside a structurally valid source-model journal creates one **distinct read observation**, including duplicate raw tokens and changed claimed principals. Claim identifiers are hashed; raw original token bytes are not placed in the journal row. Each row carries a monotonic read-attempt sequence and synthetic status, never a release permit.
- Wrong-class intents are denied **before** arbitrary attribute access. Invalid token size/type and invalid reservation/principal/receipt grant/issuer key claims yield \`D_PRIVATE_READ_ATTEMPT_LOGGED_INVALID\`. Syntactically valid intent yields \`D_PRIVATE_READ_ATTEMPT_LOGGED_HOLD\`, which is **not** a cryptographic/authentication determination.
- On malformed, inconsistent or capacity-exhausted *journal input*, return \`D_READ_JOURNAL_UNPROVEN\` with \`recorded_in_model=False\` and a **custody gap**. It would be false to say an attempt was logged when a D journal could not append. An independent ingress witness and fail-closed real D writer are essential.
- Every outcome sets \`durable_commit_proven=False\`, \`permit_historical_lookup=False\`, \`permit_receipt_release=False\`, \`permit_new_effect=False\`, and \`custody_gap=True\`. This source is merely a candidate precursor for a **future privileged service**, not a working authorization policy.
- An in-memory pure transition is **not** a durable transaction, crash-recovery mechanism or a proof of who wrote the journal. A copied Python dataclass can appear structurally valid (**RA17**). A local attempt log cannot account for messages never received by D.

## 3. Proposed ordering for a later real D, NOT implemented here

1. Independent ingress/witness acknowledges request arrival, including delivery failures before D.
2. Protected D atomically and durably commits one attempt record **per received ingress**, even for denials and duplicates. On failure, fail closed and reconcile an external witness gap. Deduplicate *effects*, **never attempts**.
3. Only **after** a durable attempt commit, verify the original token under an **independently retained issuance-time A0 signer key/registry snapshot**. Key retirement is not automatically evidence of forgery, and a claimed issuer key is not trusted. Issuance-time key compromise or untrusted timestamp/registry evidence requires hold and adjudication, not a new A0 commitment.
4. Separately authenticate the **present requester** and their **current scope-limited historical receipt-read grant**. Possession of a valid or stolen original token proves no receipt-read right; ordinary effect admission, STOP/revocation, receipt disclosure and historical integrity are distinct policies.
5. Consult v0.6 D-owned **private classification** under a controlled, versioned D store view; a history miss is **not** a new-effect permit.
6. A **separate privileged release component**, not implemented in v0.6/v0.7, must make a fresh receipt-read authorization decision and control disclosure. Persist and independently witness any actual response send; do **not** claim distributed exactly-once delivery.
7. A real D recovery needs independently monotonic authority/high-watermark, immutable historical-key enrollment and separate operators; none exists in this source packet.

The order above is a proposal, not a delivered implementation or merged interface. No single model callback or caller-furnished Python object can establish D custody, signer validity or read rights.
