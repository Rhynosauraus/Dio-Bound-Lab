## 2. Narrow source-design change: separate observation from effect

The historical D witness deliberately counted each **committed** invocation, including a duplicate dispatch that produced a second synthetic effect. The v0.3 proposal changes future synthetic semantics:

| Ledger | When it grows | Repeat dispatch behavior |
| --- | --- | --- |
| **D attempt receipts** | Every invocation *D receives and the model processes*, whether invalid, denied, a retry or a new effect | **Never deduplicated**. Separate sequence and payload digest recorded. |
| **D effect receipts** | Only after a signed, matched, A0-committed reservation satisfies current D-local grant/generation/global STOP rules and wins D's one-use claim | **At most one** effect per globally unique reservation ID *and* per `(root, run, episode, action_id)` within the model |
| **D fences** | A distinct generation, grant or run STOP record is committed in the same conceptual event order as effects | Permanent within the modeled ledger; repeated same fence is idempotent, different generation proposal conflicts |

**Consequences for M10:** Two forwarded invocations of the same valid A0 reservation are no longer expected to create two synthetic effects *under the proposed v0.3 model*. They should produce **two independently reconcilable attempt records and one effect receipt**, with the second attempt classified `ALREADY_COMMITTED_HISTORICAL_ONLY`. This is an **intentional new protocol-design refinement**, NOT a retroactive change to the v0.2 failure, and it requires a new independent semantic compatibility review. If the caller alters the reservation ID but reuses the action ID in one episode, D's action claim must also reject the second effect. If it reuses a reservation ID under a different run/action, D must classify `RESERVATION_ID_CONFLICT`.

**Consequences for N06 completeness:** A log authored by D cannot itself prove every attempted dispatch in the universe reached D. An **independently held ingress capture** and source manifest must still reconcile D attempts against B/C and N06 witness feeds. A D operator with power to remove every attempt record remains outside the positive claim until independent custody is established.

## 3. Effect admission and fence ordering

The v0.3 pure transition accepts input only through a conceptual chain:
1. Record incoming invocation's raw-payload SHA-256 (or a documented malformed payload marker).
2. Call the v0.2 exact envelope signature/binding verifier; require D-owned expected root, generation, epoch, registry, manifest, operation, action, grant, request and reservation to match **all signed values**.
3. Independently look up the exact A0 committed reservation ID, A0 commit sequence, and signed payload digest. A missing/unavailable oracle fails closed.
4. If the exact reservation was previously committed, return **historical receipt only**, with another attempt receipt and **no new effect**; after grant/generation/STOP fence, distinguish `ALREADY_COMMITTED_AFTER_FENCE_HISTORICAL_ONLY`.
5. Reject an alternate reservation for an already-committed action or an ID reused under another action/run.
6. Consult D-owned **generation fence**, **grant fence**, and irreversible global **run STOP** in the *same hypothetical serialized transition* as first effect claim.
7. Commit an attempt record plus one effect receipt/counter increment, and return an exact receipt.

The correct **real** implementation must put attempt insertion, uniqueness checks, D-local fence checks, effect insertion and counter increment in **one durable serializable D transaction**. It cannot do "check spent" in one database call and "increment effect" later. A lost response after this commit may be reconciled against the existing historical effect receipt; it must not cause a second effect.

**SQL constraint candidates:** `UNIQUE(reservation_id)` and `UNIQUE(root_id,run_id,episode_id,action_id)` on D committed effects, with **no uniqueness key on repeated attempts**. These constraints must be tested with real simultaneous writers and crash/restore experiments before asserting at-most-once effects.

**Revocation timing:** A human revocation request or an A0 decision is NOT equivalent to a durable D fence. In the source model, a previously admitted action may still commit before D's grant or generation fence. After the fence it must not. The separate v1.2/N07 D `STOP_FENCED` remains irreversible for that run. A0 stop of admissions and D stop of effects are distinct properties, as already frozen in the internal coherence plan.
