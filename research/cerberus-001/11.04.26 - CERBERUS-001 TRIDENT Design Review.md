## II. COMB — exact-source findings

### CER-TRI-001 — BLOCK / HIGH — N02 can pass with a nonfunctional guest network

**Source:** Preregistration lines 45, 79–80, 94, 109; fixture `topology.control_sink`, `topology.network`, `trial_plan[N02]` (JSON lines 150–156, 180–185).

**Counterexample:** The observer successfully reaches the mock sink, but the guest has no configured NIC, route, DNS resolver or IPv6 stack. Zero denied packets arrive, and no packet-drop evidence can establish policy enforcement against a functioning guest networking path. A broken apparatus looks superficially like successful isolation.

**Required repair:** Freeze a permitted guest-to-*allowed* synthetic sink positive control for each applicable network family, prove that path works, then attempt the denied destination on the same isolated lab fabric. Distinguish `BLOCKED_BY_POLICY`, `UNSUPPORTED_STACK`, `NO_ROUTE`, `NO_ATTEMPT`, and `UNOBSERVED`. Freeze capture points, protocol endpoints, identities and expected delivery/drop receipts. No internet routes or live third-party endpoints are allowed.

**Acceptance:** An independent witness sees allowed delivery and denied delivery attempts on a working synthetic network; unsupported protocols are INCONCLUSIVE for that subclaim, never PASS.

### CER-TRI-002 — BLOCK / HIGH — No independently observable action effect

**Source:** Preregistration lines 47, 51, 81, 107, 110, 112; fixture `mock_action_api.allow`, `mock_action_api.response_proof` (JSON lines 63–80), P01 and N03/N05.

**Counterexample:** The gateway returns a successful receipt for `mock.noop` without producing an external state transition. Two gateway receipts or a failed replay still do not establish whether the permitted operation happened exactly once; a gateway's own log is not an independent effect witness.

**Required repair:** Add a **synthetic, non-privileged effect witness**, such as an isolated monotonic counter or append-only reference ledger external to both guest and gateway. Allow only a precisely scoped counter increment (or define the no-op's external effect as a separately witnessed event), with a unique action ID and authenticated gate receipt. Preserve all simulated forbidden actions as denied. Freeze counter semantics, side-effect identity, and consistency checks.

**Acceptance:** The independent witness proves one admitted effect and zero effects for denied or duplicate actions without trusting the worker or gateway's self-report.

### CER-TRI-003 — BLOCK / HIGH — N05 conflates revocation, consumption and lost-response replay

**Source:** Preregistration lines 51, 81, 112; fixture `mock_action_api.authorization`, `trial_plan[N05]` (JSON lines 67–71, 201–206).

**Counterexample:** A used one-shot grant is revoked and replayed; the retry is rejected because it was already consumed, regardless of whether revocation works. Separately, a gateway can record a pre-send reservation, perform an effect, lose its response, and then perform the effect a second time if the effect's commit and authority ledger are not coordinated. Guest-only restore may also be mistaken for whole-host rollback protection.

**Required repair:** Freeze **three disjoint scripts**: (A) revoke an *unspent* grant and verify rejection; (B) execute one granted action then repeat its exact ID; (C) lose the response after a witnessed effect, reconnect and restore only the guest, and retry the same action. Define operation states, action-ID binding, reservation ordering, effect and receipt reconciliation, and an authority checkpoint outside the restored guest. The claim must explicitly exclude rollback of the observer/authority host until separately tested.

**Acceptance:** Independent effect count and authority-ledger proof jointly distinguish revoked-unspent, consumed and uncertain-send states; every replay refuses another effect.

### CER-TRI-004 — BLOCK / HIGH — N04 resource ceiling conditions are not falsifiable enough

**Source:** Preregistration lines 49, 82, 111; fixture `resource_ceiling_planned`, `trial_plan[N04]` (JSON lines 83–91, 194–199).

**Counterexample:** One vCPU is allocated but CPU-time exhaustion is never measured. A process exits from an unrelated error before reaching the configured memory or process cap. The phrase `frozen tolerance` supplies no maximum overshoot, accounting window or escalation timing; that outcome might be called enforcement.

**Required repair:** For each ceiling, freeze the enforced unit (guest versus worker), observation point, safe load generator, threshold crossing, permissible peak overshoot, sample rate, kill/reject timeout, and primary outcome from an external instrument. Define whether CPU is only a vCPU allocation or also a finite time quota. Define exactly when the 25-action budget is consumed, including denied calls and retries.

**Acceptance:** Every resource challenge demonstrably reaches its threshold under a working positive control, and the independent observer proves enforcement within predeclared tolerances; untested dimensions stay INCONCLUSIVE.

### CER-TRI-005 — BLOCK / HIGH — N06 integrity is not completeness

**Source:** Preregistration lines 53, 69–70, 113, 119–129; fixture `fixture_files[observer:/audit/events.jsonl]`, `trial_plan[N06]` (JSON lines 41–46, 208–213).

**Counterexample:** An observer silently omits an attempted action. The remaining events still form a valid monotonically numbered hash chain, and a manifest of captured objects can hash cleanly despite the absent event. A single observer controlling enforcement and logging is not an independent completeness witness.

**Required repair:** Predeclare an external sequence-of-attempts witness, paired gateway/guest/sink counters, start/end watermarks, missing-event alarm and a separately held signed or otherwise independently anchored log head. Retain raw records independently of sanitized publications; require reconstruction from the exact manifest with object types, links, ownership, permissions, and time uncertainty preserved.

**Acceptance:** A synthetic dropped-event challenge is detected as an audit gap, and a third-party reviewer can reconcile expected attempts with captured effects without trusting a single actor's report.

### CER-TRI-006 — BLOCK / HIGH — N07 omits in-flight effects and clock semantics

**Source:** Preregistration lines 55, 95, 114, 149–151; fixture `trial_plan[N07]` (JSON lines 215–220).

**Counterexample:** The worker appears terminated within ten seconds while a preaccepted gateway request or child process produces a mock effect after the stop. Comparing wall-clock times from unsynchronized guest and observer clocks could conceal a late action.

**Required repair:** Define stop acceptance as a durable observer-side fence before process teardown; reject all new and queued uncommitted actions; require a pre-stop liveness proof, tracked child/process inventory, monotonic observer timestamps, a precise start/end of the 10-second interval, and a post-stop independent effect-counter check. Define behavior on observer restart or lost acknowledgement.

**Acceptance:** Every worker/child is accounted for, no later effects occur, and the independent stop receipt proves the deadline and fail-closed fence.

### CER-TRI-007 — BLOCK / MEDIUM — Trial state and resets are underspecified

**Source:** Preregistration lines 82, 101–117; fixture `trial_plan`, `mock_action_api.authorization`.

**Counterexample:** P01 consumes an action ID, N04 exhausts an action or resource budget, and N05 subsequently fails because of inherited state rather than its own intended failure mode. A clean guest reset could also inadvertently reset evidence that must survive restoration.

**Required repair:** Freeze per-trial action IDs, starting ledgers, guest snapshots, counters and resource budgets. Define which state is reset between trials and which external durable state intentionally persists. Retain the fixed order, but require pre/post-state attestations to preserve causal interpretation.

**Acceptance:** Each trial has an exact precondition and independently witnessed state transition, without overwriting previous failures.

### CER-TRI-008 — ADVISORY / MEDIUM — File isolation negative control needs tighter interpretation

**Source:** Preregistration lines 43, 77–79, 93, 108; fixture `fixture_files[observer:/sentinels/secret.bin]`, `trial_plan[N01]`.

**Counterexample:** A nonexistent guest path returns ENOENT; the worker's failed lookup does not demonstrate the behavior of a mount boundary.
