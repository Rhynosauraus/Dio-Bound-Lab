## 1. Attack model and exact guarantee

**DIO-CER-004:** Verifier V reads A0 generation `g=4`, validates Q under Q4, pauses; H-authorized rotation revokes Q4 and commits `g=5`; V resumes and admits a Q4 request using its cached, formerly valid proof. All old signatures may remain authentic, yet admission is stale.

**Intended safety properties (source-design requirements, not deployed facts):**

- **A1 — No stale admission:** A0 only commits an admission reservation if the authority generation and registry digest in the request equal A0's **current, active** values **in the same linearizable transaction** that creates the reservation. A prior read, signed historical checkpoint or cached validation is not sufficient.
- **A2 — Rotation vs admission:** At most one wins the serialization order. Once A0 has entered durable `ROTATION_PREPARED`, it refuses all new reservations for retiring generation `g`. If the admission reservation committed first, it is historically valid but does not guarantee an effect.
- **E1 — No post-rotation old-generation effect:** A0 may commit `g+1 ACTIVE` **only after** D durably commits a **generation fence for g** that is serially ordered with D's synthetic effects. Any effect after D's fence using `g` is forbidden. Because A0's rotation commit causally follows D's fence receipt, an old-generation effect cannot linearize after the completed rotation.
- **E2 — In-flight reservation is not permanent authority:** A successfully admitted but unsettled `g` reservation may produce its *single* effect before D's fence. If the fence commits first, D must reject the old reservation, even though A0's earlier admission was valid. This deliberately prevents a "check once, execute later" loophole.
- **S1 — Emergency STOP remains dominant:** The separate v1.2 D `STOP_FENCED` for run shutdown is irreversible and must be checked in the same D effect transaction. No generation rotation or new root reopens an N07-stopped run.
- **U1 — Uncertainty is not success:** Unreachable/ambiguous A0 or D, admission/rotation conflict, or missing durability evidence triggers refusal and an explicit UNKNOWN/INCONCLUSIVE disposition, never optimistic admission or a false PASS.

**Claim ceiling:** The above guarantees hold only *if* the proposed A0 linearizable reservation store, D durable effect/fence transaction system, independent custody and crash/rollback assumptions are independently verified later. Source review alone establishes no enforcement or physical trust-domain independence.

## 2. Protocol roles and trust domains (no implementation claimed)

**A0 — generation/reservation authority:** Outside B, C, guest restore and mutable trust registry. Stores authoritative `(root_id, generation, registry_digest, activation_epoch, phase, previous_digest)` plus an immutable per-attempt one-use reservation ledger. Requires linearizable conditional transactions and crash-durable anti-rollback state **outside the relevant snapshot domain**. The A0 read method may return historical information but has **no authority to grant admission**. Only `RESERVE_IF_CURRENT` may grant.

**B — gateway:** Verifies request signature, role/scope, v1.3 exact manifest membership and purpose, and obtains an A0 reservation. B may say `ADMITTED` only after an exact signed/durable A0 reservation response; it cannot locally cache an authorization verdict or invent a reservation. B cannot commit generation state.

**D — synthetic effect/stop witness:** Owns an independent durable transaction log containing all committed non-idempotent `mock.counter_increment` effects, irreversible **per-generation fences**, and the v1.2 global `STOP_FENCED` run fence. D validates the A0 reservation token and the **D-local durable fences at the same linearization point as the effect**. The synthetic effect counter remains intentionally **non-deduplicating** to expose duplicate gateway dispatches; exactly-once prevention is an A0/B obligation. D must log duplicate invocations and any actual second effect for adverse scoring.

**H/G1/G2, Q/F/E, J:** Keep v1.4 human bootstrap/guardians, v1.3 complete challenge manifest, and separate adjudicator requirements. Key ownership, administrators, keys, host/backup domains, transaction engine and checkpoint store remain **UNASSIGNED_NOT_BUILT**.

**Non-assumption:** A0 and D are independently controlled, so this contract **does not** claim a single distributed atomic transaction across both machines. The security ordering is deliberately one-way: **(1) A0 freezes admissions → (2) D fences old-generation effects → (3) A0 activates new generation**. If a design cannot enforce those steps and verify their durable receipts, the rotation stays pending and effects/admissions fail closed.

## 3. Conditional admission: A0 RESERVE_IF_CURRENT

Each attempted synthetic action binds the exact tuple:

`(root_id, authority_generation, activation_epoch, registry_digest, manifest_id, manifest_sha256, run_id, episode_id, trial_id, attempt_id, action_id, grant_id, operation, request_sha256, reservation_nonce)`.

The **precheck** at B may be performed for efficiency but is NOT permission to dispatch. **Admission** linearizes at A0 in one durable conditional transaction:

1. Check that independently established T0/trust lineage matches, `phase=ACTIVE`, generation/epoch/digest match the request, role key is valid for exact scope, manifest belongs to the bound generation, grant is live, budget is available, and `(run_id, attempt_id/action_id, grant_id)` has not already been reserved or consumed.
2. Conditionally create one `RESERVED` ledger entry with sequence/transaction ID, immutable request hash, expiry bounds (requires reliable D2 time source), and current generation. Charge budget in the same transaction. Return an A0 authenticated reservation token bound to those exact fields and to A0 commit sequence.
3. If any check fails, return a **durable refusal**, such as `STALE_AUTHORITY_GENERATION`, `ROTATION_PENDING`, `FENCED`, `DUPLICATE_RESERVATION`, `WRONG_MANIFEST`, `NO_GRANT`, `BUDGET_EXHAUSTED`, or `FRESHNESS_UNPROVEN`. No dispatch effect follows.
4. If the A0 result is lost after its commit, the gateway MUST query the exact reservation by immutable ID. It may report `DELIVERY_UNCERTAIN` but must not issue a new action ID/reservation or assume no effect. It cannot replay a non-idempotent effect to "get a response."

**Generation/purpose guard:** A current Q-key registry and a manifest signed under generation 4 cannot be silently reused under generation 5. Any fresh W0/F1 needs independent Q/F/E authority binding and exact manifest validation before eligible admission. Old signatures may remain historical evidence only.

## 4. Safe rotation/revocation without fictional atomicity

**R0 — request:** H authorization and G1/G2 signature checks occur as specified in v1.4. A human **requests** rotation/revocation, but this is *not yet proof of effective revocation*. Signer/key decision rules and trust-anchor verification remain unchanged.

**R1 — A0 PREPARE:** A0 atomically transitions `ACTIVE(g)` to durable `ROTATION_PREPARED(g,g+1,proposal_digest)`. This fences **new admissions** for g (or all scopes conservatively) at A0. Previously committed reservations remain `RESERVED`, not magically invalidated at this step. If crash happens, recovery resumes in pending/deny state, never silently ACTIVE(g).

**R2 — D generation fence:** The independent rotation controller sends the exact prepared epoch/proposal digest to D. D durably commits `GENERATION_FENCED(g, proposal_digest)` in the **same serializable effect/fence log** that commits synthetic effects; D retains this fence beyond process restart and guest restore. D returns a signed `(D_log_sequence, generation, proposal_digest, fence_commit_receipt)`.

**R3 — A0 activation:** A0 verifies D's exact receipt and atomically commits `ACTIVE(g+1, new_registry_digest, new_epoch)` and `RETIRE(g)` plus previous-head evidence. This is the **effective generation-rotation linearization point**. No ordinary B role may fabricate it.

**R4 — subsequent action:** B may reserve at g+1 only after updated manifest/grant scope is independently established. D accepts effects at g+1 only if any previous global run STOP is absent, relevant generation fences are correct, and a fresh exact A0 reservation token is supplied. No stale g effect survives D's g fence. If D fences old g but A0's activation fails, the system stays pending with old effects forbidden and new admissions denied until independently reconciled; it does **not** unwind D's fence.

**Emergency stop distinction:** A human emergency stop demands the independent D global `STOP_FENCED` immediately; rotation is NOT a substitute for that stop. If D is unreachable, admission is disabled and the separately tested outer emergency isolation path is required; **no unverified assertion that every in-flight effect stopped**. Absence of a durable fence ⇒ STOP_UNPROVEN / INCONCLUSIVE; a confirmed late prohibited effect ⇒ BLOCK.

**Threat assumption:** A0 and D do not both roll back to an old state under the same adversary. If a whole-lab rollback erases both fences and the anti-rollback high-watermark, continuity is UNKNOWN and no positive guarantee is claimed.
