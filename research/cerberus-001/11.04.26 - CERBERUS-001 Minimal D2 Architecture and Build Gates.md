## 2. Concrete source-only technology candidates, not installed choices

- **State-machine language:** Python 3.x **candidate only**, exact version/image/source hashes assigned during D2 after source and environment examination. The core authority should be a small deterministic transition function, independent of transport serialization. No library/SDK install is authorized.
- **A0 ledger:** candidate SQLite transactional database with one-writer serializable conditional generation/reservation transitions. The actual \`BEGIN IMMEDIATE\`/constraint behavior, durability flags, filesystem, power-loss semantics, anti-rollback proof, and read-after-restart checks must be independently tested before claiming atomicity. An external checkpoint must survive the specific snapshot domain; a local database alone does not.
- **D ledger:** separate candidate SQLite transaction domain containing \`EFFECT_COMMITTED\`, \`GENERATION_FENCED\`, \`STOP_FENCED\`, and a non-deduplicating counter. It must reject old-generation effects *in the same durable transaction ordering* as the fences. This is independent of A0, so no cross-host atomic transaction is assumed.
- **Wire:** narrow length-bounded, version-tagged request/receipt envelope carrying exact source/manifest digests, run/episode/action/reservation IDs, generation and registry digest. Future authenticated transport, key identifiers, replay rejection, expiry and binary hashes must be frozen. No unauthenticated network control is part of an acceptable D2 configuration.
- **Lab isolation:** worker process unprivileged in dedicated Linux VM, read-only synthetic fixture and cgroup-v2 quotas inherited from v1.2; no outside route and no real PS5/host paths. Existing v1.1 positive network/file controls remain mandatory to prevent broken-apparatus false PASS.
- **Storage:** append-only/versioned raw objects with independent signing and access ownership; SHA-256 of exact bytes, length, causal sequence receipts and reconstruction metadata. **Hashes by an operator who can remove all originals do not establish completeness.**

No specific provider, cost, physical host, root key, operational identity, filesystem mount or external endpoint has been chosen. No real infrastructure is presently evidenced by these proposals.

## 3. Minimal API and durable authority contract

Only these logical operations are necessary for first synthetic qualification. **All are planned functions, not exposed endpoints.**

| Logical operation | Ownership | One required atomicity/fail-closed condition |
| --- | --- | --- |
| \`A0.ACCEPT_RELEASE_IF_CURRENT\` | A0 | Exact Q/F/E manifest ID+digest, current generation/epoch/registry, stop state, unused release ID and durable acceptance committed together; stale F→C bytes may arrive but cannot become newly runnable |
| \`A0.RESERVE_IF_CURRENT\` | A0 | Current generation, trust anchor, grant, budget, stop, exact manifest and one-use reservation committed in one conditional transaction |
| \`A0.PREPARE_ROTATION\` | A0 | \`ACTIVE(g) → ROTATION_PREPARED(g)\` serializes against **both** release acceptance and admission; no new g reservations after preparation |
| \`D.FENCE_GENERATION\` | D | Old-g generation fence committed durably in D's **effect** serialization order; exact A0 prepare digest and causal receipt |
| \`A0.ACTIVATE_ROTATION\` | A0 | Commit g+1 only after a verified, durable D fence receipt; unknown receipt leaves \`ROTATION_PREPARED\` |
| \`A0.STOP_PREPARED\` | A0 | No new release acceptance/admission **after A0's own durable STOP commit** |
| \`D.STOP_FENCED\` | D | No synthetic effect **after D's own durable global STOP commit**; N07 global stop is irreversible for that run |
| \`D.APPLY_SYNTHETIC_EFFECT\` | D | Check exact A0 reservation token, local generation fence and global stop in the same transaction that increments synthetic counter; do not deduplicate counter effects, so a duplicate B dispatch remains observable |
| \`J.RECONCILE\` | independent examiner | Reconstruct original Q/F/E challenge manifest and exact A0/D/C causal receipts; separate missing proof (INCONCLUSIVE) from proven forbidden effect (BLOCK) |

**Safety-critical ordering:** For rotation/revocation, A0 PREPARE (no new admissions) → D generation fence (no new old-g effects) → A0 ACTIVATE(g+1). A successfully *admitted* old-g reservation may still effect **before** D's fence; after it must be rejected. A mere human rotation request is not a completed revocation.

**Two STOP guarantees, not a false unified guarantee:**
- D-first emergency stop establishes **effect stop after D's fence**, even if A0 still issues harmless but ineffective reservations for a short interval. It does *not* prove "no admission since D stop".
- A0 \`STOP_PREPARED\` establishes **admission/release stop after A0's own commit**, even if effects already admitted before that commit remain unproven until D fences.
- Only independently verified **both** A0 and D receipts (plus worker-tree termination evidence) can support combined STOP completion. Never compare unsynchronized wall-clock timestamps as a substitute for receipt ordering.
- If a human requires a stricter claim of no admissions after *the instant D* stops, the proposed separate stores do **not** provide it. Narrow the claim or design and separately qualify a shared linearization boundary; do not fabricate distributed atomicity.

**Known limitation:** D deliberately counts every committed synthetic invocation and does not suppress a duplicate gateway dispatch. A0's one-use reservation policy alone does not prevent a compromised B from forwarding one token twice. The negative test must reveal the duplicate and BLOCK. Do not claim global exactly-once effect protection until B/delivery semantics are separately proven.

## 4. Recovery and custody: immutable causal evidence

Required durable event fields: protocol/version, source SHA-256, \`run_id\`, \`episode_id\`, \`trial_id\`, manifest commitment, exact attempt/action/grant/reservation IDs, \`root_id\`, generation, activation epoch, registry digest, actor ID, operation/result, actor-local transaction sequence, raw-byte length+SHA-256, prev-record digest and separately held signing identity. UTC time and clock uncertainty may assist forensics, but do **not** create global ordering between unrelated machines.

- **A0 crash after successful reservation, response lost:** Query by immutable reservation ID and return its actual state; never re-admit speculatively or re-dispatch an uncertain effect.
- **D crash after durable generation/global fence, response lost:** Restore D local durable state and independently reconcile receipt before any effect; A0 stays pending until verified.
- **A0 active g+1 but D state inaccessible:** No positive revocation/containment claim without independently retrieving D's fence/monotonic history. Deny new work until reconciled.
- **Mixed A0/D snapshot restore:** Compare independently retained high-watermarks and authority generation; conflicting or missing checkpoint ⇒ fail closed and INCONCLUSIVE. If the *same* operator can roll back all stores and checkpoints, the claimed proof is invalid.
- **N07:** STOP_FENCED is final for run, with no role-key rotation or new manifest reopening the same run. A new future run requires separate approval and fresh IDs.
- **Audit completeness:** C must obtain the original independently frozen Q/F/E source, not trust its own expected-count export. DIO-CER-001/002/003/004 remain disclosed, not blind.
