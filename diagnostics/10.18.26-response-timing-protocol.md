# DIO Lab — Diagnostic 001 Protocol: Response Timing and Missed Replies

**Protocol date:** 10.18.26  
**Status:** Planned; not yet executed as controlled trials  
**Environment:** Existing group chat

## Research question

Do explicitly addressed messages receive more consistent replies than ordinary conversational follow-ups, and how variable are the observed message-to-reply intervals?

## Definitions

- **Direct address:** A short prompt explicitly addressing `ChatGPT` or `Dio`.
- **Follow-up:** A clear request that immediately follows an assistant response without a repeated name.
- **Latency:** Seconds between the visible timestamp of the test message and the first assistant response to that test; not model inference time.
- **Answered within window:** A relevant response appears within 60 seconds of the test message.
- **Unanswered within window:** No relevant response appears within 60 seconds; do not call it a processing timeout.
- **After reminder:** An explicit reminder is sent only after the 60-second observation window, and a response follows; record both intervals separately.

## Trial procedure

1. Prepare 10 comparable, short, benign requests, each answerable without web research or external tools. Avoid personal or sensitive topics.
2. Alternate five direct-address and five clear immediate-follow-up trials where possible. Preserve the intended condition; if a trial does not meet it, mark it invalid rather than silently relabeling.
3. Record the message timestamp in UTC, condition, exact prompt, and whether it immediately followed an assistant response.
4. Do not send another message for 60 seconds. If a response appears, record its timestamp and relevance.
5. If no response appears, record `unanswered_60s`. A reminder may then be sent, with its own timestamp. Record whether and when a response appears afterward.
6. Log interruptions, overlapping group messages, network/client issues, and changes in request difficulty as confounders.
7. Compare answer rate and median latency separately by condition. Report all trials including failures; do not pool reminder-to-response time with original prompt latency.
8. Replicate in another session only if authorized; treat it as a distinct environment, not an interchangeable control.

## Data fields

`trial_id,condition,prompt_timestamp_utc,reply_timestamp_utc,latency_seconds,outcome,reminder_timestamp_utc,reminder_to_reply_seconds,confounders,notes`

Use `NA` when an interval is not measurable. Do not enter an invented zero.

## Decision rules

- Five trials per condition are exploratory only; report raw values and descriptive statistics, not proof of a cause.
- A higher reply rate following explicit address supports investigating message-selection effects, but does not isolate the underlying mechanism.
- If all trials receive replies, that does not invalidate earlier observations; it bounds the behavior in the test window.
- A missing response and a delayed response must remain distinct classifications.
- Functional interface testing of interactive controls is a **separate** study, not a latency trial.
