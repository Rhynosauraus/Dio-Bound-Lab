# DIO Lab — Qi++ Conceptual Language Specification (v0.1)

**Date:** 10.18.26  
**Type:** Collaborative creative language-design experiment  
**Implementation status:** Fictional specification only; no parser, type checker, runtime, or compiler was built or tested.

## Prompt and premise

A participant asked what language would represent a spiritual mentor arranging a house according to feng shui. The assistant jokingly named **Qi++**, and was then asked to write a specification. The result was a deliberately playful domain-specific language (DSL) proposal.

**Tagline:** 'If it compiles but the room feels wrong, it does not compile.'

## Design sketch

Qi++ is a furniture-oriented language for describing spatial arrangements, relationships, and feng shui-inspired rules. Its proposed core abstraction is **flow**, not control. It distinguishes objects such as rooms, furniture, and entrances from symbolic attributes such as direction, element, and qi state.

```qipp
house Home {
    entrance Door facing SOUTH;

    room Office {
        desk Workstation {
            position = command;
            facing = EAST;
        }

        plant Bamboo near Workstation;
        mirror Reflection opposite Window;

        require qi.flow != BLOCKED;
        avoid desk.back_to(Door);
    }
}
```

Proposed primitive types:

```qipp
type Furniture;
type Direction = NORTH | SOUTH | EAST | WEST;
type Element = WOOD | FIRE | EARTH | METAL | WATER;
type Qi = FLOWING | STAGNANT | BLOCKED;
```

Relationships can be expressed declaratively:

```qipp
chair faces desk;
desk commands door;
bed avoids direct_line(door);
```

## Proposed compilation stages

1. **Placement:** Check physical fit and spatial feasibility.
2. **Relation:** Evaluate declared spatial relationships and constraints.
3. **Harmony:** Evaluate the arrangement against a user-selected symbolic ruleset.

Illustrative, invented diagnostics:

```text
Q100: Sofa obstructs primary qi path.
Q214: Mirror reflects bed.
Q301: Desk lacks command position.
Q404: Auspicious corner not found.
Q500: Technically valid. Spiritually questionable.
```

## Additional humorous semantics

A **decluttering collector** replaces garbage collection and respects sentimental roots:

```qipp
release objects
where !used_within(months: 12)
  && !sparks_joy;
```

```text
ERROR Q721:
Grandmother's weird ceramic goose cannot be released.
Reason: sentimental_root detected.
```

The language also proposes the hazardous statement `consult mother_in_law;` as a joke, not a real executable construct.

## Observations versus claims

**Observed:** A coherent, themed language sketch with example syntax, type names, proposed compilation passes, and diagnostic messages was generated in response to the prompt.

**Not established:** That the syntax is formally unambiguous, that the examples parse, that constraint solving is implemented, that any feng shui framework has been faithfully encoded, or that a working compiler exists.

## Reproducible next step

Define a grammar, object model, and machine-checkable rules for the sample program. Implement a small parser and validator, then test valid and invalid room layouts. Keep aesthetic and cultural rules explicit and configurable rather than claiming a universal measure of harmony.

**Status:** Idea archived for potential prototyping. No technical execution test performed.
