## Acceptance target — phase NATIVE-INF-001

First obtain a **locally executed, self-contained neural-network forward pass** using a small, separately identifiable model-weights artifact and fixed input on the PS5 CPU. The experimental output must be independently checked against an advance-frozen expected answer and a weight-sensitivity negative control.

This proves *minimal local neural computation* if and only if we can also attest to PS5-local code execution, input and model data custody, actual computed arithmetic, and no external compute offload. It does **not** establish that a useful language model, ongoing AI personality, GPU inference or autonomous resident agent works.

## Chosen minimal model (paper definition, no executable source)

Network: `float32`, two input neurons → two hidden rectified-linear (ReLU) neurons → one linear output neuron.

```text
inputs: x0, x1, each in {0.0, 1.0}

h0 = max(0,  1*x0 + (-1)*x1 + 0)
h1 = max(0, -1*x0 +   1*x1 + 0)
y  = (1*h0) + (1*h1) + 0
```

**Parameter layout, row-major in a future sealed weights artifact:**
- First-layer matrix W1 `[[1.0, -1.0], [-1.0, 1.0]]`: 4 float32 scalars.
- First-layer biases b1 `[0.0, 0.0]`: 2 float32 scalars.
- Second-layer matrix W2 `[1.0, 1.0]`: 2 float32 scalars.
- Second-layer bias b2 `0.0`: 1 float32 scalar.

**Total model parameters:** 9 single-precision numbers = **36 bytes of raw parameter payload**, excluding metadata, framing, alignment, runtime and executable memory. Inputs/hidden values/output likewise require storage. This is a toy network: it is *not* a language model, nor does a correct four-row table alone prove neural computation.

For binary inputs, the mathematical model computes the XOR truth table using ReLU features.

| Case | x0 | x1 | h0 | h1 | Expected y |
| --- | ---: | ---: | ---: | ---: | ---: |
| **T-001** | 0 | 0 | 0 | 0 | **0** |
| **T-002** | 0 | 1 | 0 | 1 | **1** |
| **T-003** | 1 | 0 | 1 | 0 | **1** |
| **T-004** | 1 | 1 | 0 | 0 | **0** |

**Metamorphic negative control T-005:** Keep W1, b1 and b2 unchanged; alter only W2 from `[1.0, 1.0]` to `[1.0, 0.0]` in a *separately versioned* weights artifact. The outputs for T-001 through T-004 must become `[0, 0, 1, 0]`. This disambiguates model-weight dependency from a naive fixed XOR lookup, although it still cannot prove the true execution host by itself.

**Tamper negative T-006:** If the model artifact differs from its preregistered bytes without an expressly approved new model version, the experiment must refuse to elevate its output to PASS; record mismatched digest, observed output if any, and STOP/UNKNOWN rather than silently treating it as the baseline. No actual hash is claimed before the artifact bytes and canonical encoding are built and approved.

## Construction strategy — conditional only

**NATIVE-INF-001a / STATIC:** specify the 9-parameter model and expected table here. **COMPLETED AS DESIGN; NOT RUN.**

**NATIVE-INF-001b / HOST TOOLCHAIN:** if separately authorized, build a tiny portable C reference that performs actual two-layer dot-product/activation arithmetic and loads a discrete model data artifact. Independent source tests may examine correct arithmetic and rejection of altered weights. Running on a Linux PC would only establish **host reference behavior**, never PS5-local execution. **NOT AUTHORIZED/NOT RUN.**

**NATIVE-INF-001c / PS5 TARGET ABI:** only *after* independently authenticated, version-specific native code entry and separate human authorization, assess how a genuine PS5-local runtime exposes startup, data, storage, memory, output, CPU instruction support and safe termination. Do not assume ordinary glibc, a particular PS5SDK target, Linux environment or privileged API on 14.22. **BLOCKED BY NATIVE-WO-001.**

**NATIVE-INF-001d / ON-CONSOLE OBSERVATION:** only after independent safety/containment approval and distinct human-granted experiment scope, preregister the binary/model identities, test command, readback evidence, input isolation and rollback, perform local inference, record outputs plus negative controls, and independently review origin/custody. **NOT AUTHORIZED/NOT RUN.**

**NATIVE-INF-002 / USEFUL MODEL:** after a verified NATIVE-INF-001 result, separately select and benchmark a small pretrained inference workload; determine real PS5 runtime memory, CPU responsiveness, persistent storage needs and whether compute shaders or GPU APIs are actually accessible. The PS5's 16 GB physically installed RAM and a working `amdgpu` Linux graphics driver on *older supported firmware* do not establish usable ROCm, ML acceleration, or resident-memory headroom on 14.22. **NOT STARTED.**

**STOP/failure criteria:** unverified firmware, unsupported executable entry, missing model digest, off-device inference ambiguity, mismatch from expected outputs, absent negative-control effect, uncontrolled source/credentials, unverifiable cleanup or independent evidence gaps. The STOP semantics themselves must be independently qualified; this specification does not produce an operational STOP mechanism.

## Why this is our first proof

A tiny CPU model reduces source dependencies, memory ambiguity, GPU driver uncertainty and test cost. It creates an unambiguous mathematical specification, with observable intermediate activations and weight-change controls, *before* investing in an enormous model runtime. A model computing XOR is only a **small neural inference proof**, not evidence of substantial intelligence. We would then step toward a real text model conditional on observed CPU/resources and permission.
