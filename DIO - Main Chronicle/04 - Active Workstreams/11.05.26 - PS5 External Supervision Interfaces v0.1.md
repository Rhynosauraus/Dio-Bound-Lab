## Design principles for any future interface

- **Observation is not actuation.** Reading a screen frame cannot itself authorize a controller input. A separate, human-controlled input release gate is needed even if an external observation method works.
- **A remote account is not an AI credential.** Do not give the worker a Sony sign-in, session cookie, account state or access to a password manager. Official Remote Play requires a user account, which is a new security boundary.
- **A capture device is not a bypass.** HDCP protects media; no instruction here authorizes circumventing protection. Any ordinary gameplay capture plan would require informed user approval of a settings change and any needed hardware, and clear exclusion of protected media.
- **None of these is an autonomous device-interface qualification.** Synthetic source tests on GitHub may be useful but do not establish real-world isolation, effect STOP or external A0/D/C authority.
- **Human stop and privacy first.** The future design must include controls for recorded frames, bystanders and personally identifiable material in menus, frame storage/retention and deletion, and a user-controlled emergency stop.
- **Version-dependent paths must remain distinct.** PS5 firmware 14.22 is reported context, not a newly observed device state. A new native exploit release would require a new source-dated evaluation; never re-label older negative results.

## Next bounded, source-only design test

Develop a paper **minimum-control loop** with:
1. No-device synthetic fixture containing a mock observation frame and an operator-visible action proposal.
2. Policy classifier that produces `OBSERVE_ONLY`, `PROPOSE_ACTION` or `STOP`.
3. Human approval *before any hypothetical input*, immutable intent/decision receipt and no runtime action.
4. Adversarial cases: forged observation, stale frame, wrong account binding, missing approval, conflicting STOP, protected media, and evidence loss.
5. Distinct examiner review of the paper contract; no user console or Mac access until separate human consent.

**Current decision:** A1 official user remote access is documented, but AI automation is not. A2 gameplay capture is technically supported by capture vendors conditional on an HDCP settings change but is **not** authorized or tested. A3 mock is viable as source research only. B native 14.22 remains unsupported in examined upstream sources.
