## 1. North Star of the classroom

Teach and independently challenge the smallest **off-device reasoning and review loop** for an imagined PS5 screen:

> **Synthetic observation → Bounded action proposal → Explicit human decision claim → Append a source-model event → Never transmit a device action.**

The *parent project* seeks to determine whether a user-owned original-model PS5 can safely participate in a controlled AI experiment, comparing external supervision and firmware-dependent native access. This classroom does **not** turn that hypothesis into device control. It is a generic deterministic state machine built from invented "fictional training menu" values.

DIO/TRIDENT independently examines source, contradictions, provenance and adversarial coverage **at milestones**, not every routine development edit. Ozymandias is a builder/teacher; neither source code nor a user-claimed reviewer string establishes an independently authenticated human.

## 3. Proposed state-machine phases and truth ceiling

| Phase | Input | Model result (prediction, NOT observed) | What it cannot prove |
| --- | --- | --- | --- |
| **OBSERVE** | `MockFrame` with fixed synthetic-only kind, increasing sequence and visible mock actions | `MOCK_FRAME_OBSERVED` plus locally hashed structured *invented* frame data | The string "SYNTHETIC_MENU_ONLY" is **not authenticated** and cannot prove input provenance; no real pixels or PS5 frame was read |
| **PROPOSE** | One `Proposal` matching current sequence/digest and one of the visible actions | `PROPOSAL_AWAITING_HUMAN`; pending state, no effect | Does not execute, connect, input, or prove an LLM selected wisely |
| **REVIEW** | `HumanDecisionClaim` matching the pending proposal / current frame | `SIMULATED_APPROVE_CLAIM_RECORDED`, `...DENY...`, or `...STOP...` | A claim of approval is **not a cryptographic human authentication**; a malicious caller could fabricate it |
| **RECORD** | Pure in-memory `MockEvent` numbered sequence | `recorded_in_model=True` if source syntax and space allow | Not persistent, independent C custody, tamper-proof audit, or an actual run receipt |
| **REFUSE / STOP** | Stale frame, forged bindings, corrupt event row, full event log or STOP flag | Source intends explicit refuse or custody-gap status | No physical process kill, host/network isolation, effect fencing, recovery or protected device STOP |

**Global invariant:** Each `MockOutcome` always returns `external_action_permitted=False`, `approval_authenticated=False`, `durable_commit_proven=False`, and `custody_gap=True` including on modeled APPROVE. There is no real action-dispatch interface to call.

**Known simplifications:** Frame content is a tiny schema of IDs/title/available actions, not images. The mock "AI" suggestion selects the first allowed action deterministically; it is not an inference model, PS5 computer vision, or teaching of a deployed agent. Negative test expectations have not been independently executed. A real future observation source needs separate origin authentication, privacy filtering and independent policy enforcement.

## 4. Three worked examples (PREDICTIONS ONLY)

### Worked A — ordinary mock menu

- `MockFrame("FAKE-SCREEN-1", 1, "SYNTHETIC_MENU_ONLY", "Fictional Training Menu", ("MOVE_DOWN", "SELECT"), False)`.
- If statically valid, OBSERVE is expected to produce `MOCK_FRAME_OBSERVED`.
- `suggest_one_mock_action` is expected to propose `MOVE_DOWN` and create `PROPOSAL_AWAITING_HUMAN`.
- A matching `HumanDecisionClaim(..., decision="APPROVE")` is expected to create `SIMULATED_APPROVE_CLAIM_RECORDED`, but **no real permission or device action**.

### Worked B — stale image or substituted approval

- If a new screen with a higher sequence supersedes the proposal, the previous pending approval is invalidated. Attempting an old proposal should be `REFUSED_STALE_PROPOSAL`; an old approval with no pending proposal should be `REFUSED_NO_PENDING`.
- If the input approval digest does not bind to the current frame and proposal, `REFUSED_REVIEW_BINDING` is expected.
- No source test has yet observed either prediction.

### Worked C — STOP or custody failure

- If `simulated_stop` is recorded in the model, subsequent proposed actions should be `REFUSED_STOPPED`.
- If an exact-class journal event is missing a required instance field, the model should return `EVIDENCE_GAP_STOP` with no reconstructed evidence and no false model-append claim.
- The STOP is **only a modeled flag**, not the termination of a real AI worker, VM or PS5 action.

## 5. Guided teaching then independent qualification

1. **Explain:** show the difference between observation, proposal, approval *claim*, authenticated authority, effect and independent custody.
2. **Demonstrate:** walk through Worked A, B and C as *source predictions*, marking which properties are unproven.
3. **Explain back:** require the candidate to identify why an unauthenticated APPROVE cannot become an external button press and why stale frames invalidate a pending action.
4. **Guided practice:** study MOCK01–MOCK12, document corrections, no execution.
5. **Fresh solo challenges:** study MOCK13–MOCK24 or new held-out cases devised by the examiner; do not coach while assessing final outcomes.
